# Candle: implementation

This document describes how candle is implemented: the concrete types, algorithms, files and
build mechanics. The components and how they fit together are described in
[architecture.md](architecture.md).

## Repository and build

- A Cargo workspace (`Cargo.toml`) with `candle-core`, `candle-nn`, `candle-transformers`,
  `candle-examples`, `candle-datasets`, `candle-pyo3`, `candle-wasm-examples/*`,
  `candle-wasm-tests` and `tensor-tools` as members. `candle-kernels`, `candle-metal-kernels`,
  `candle-flash-attn`, `candle-flash-attn-v3`, `candle-onnx` and `candle-book` are excluded from
  the workspace and built as path dependencies, so a default workspace build needs no GPU
  toolchain.
- Versions and shared dependencies are pinned once in `[workspace.dependencies]`.
- Approximate size: `candle-transformers` ~91k lines in 216 files (131 entries under `models/`),
  `candle-core` ~47k, `candle-nn` ~10k, `candle-metal-kernels` ~8k lines of Rust plus `.metal`
  sources.
- CI: `.github/workflows/rust-ci.yml` (fmt, clippy, tests), `ci_cuda.yaml`, `python.yml` and
  `maturin.yml` (Python bindings), `trufflehog.yml` (secret scanning).
- Features in `candle-core/Cargo.toml`: `cuda` (pulls `cudarc` and `candle-kernels`), `cudnn`,
  `nccl`, `cutile`, `metal` (pulls `objc2-metal`, `objc2-foundation` and `candle-metal-kernels`),
  `metal-debug-labels`, `mkl` and `accelerate`. Disabled backends compile against
  `dummy_cuda_backend.rs` and `dummy_metal_backend.rs`, which implement the same interface and
  return errors.

## candle-core

### Tensor

`src/tensor.rs`. `Tensor` is a newtype around `Arc<Tensor_>`:

```rust
pub struct Tensor_ {
    id: TensorId,                  // unique id, the key of the gradient store
    storage: Arc<RwLock<Storage>>, // shared between a tensor and its views
    layout: Layout,                // shape, strides (in elements), start offset
    op: BackpropOp,                // Option<Op>: how it was computed, when tracked
    is_variable: bool,
    dtype: DType,
    device: Device,
}
```

- Cloning a `Tensor` clones the `Arc`. View operations (`reshape`, `transpose`, `narrow`,
  `broadcast_as`, `squeeze`, `i(..)`) build a new `Tensor_` with the same `storage` `Arc` and a
  new `Layout`.
- `contiguous()` copies only when the layout is not already C-contiguous.
- Element-wise and reduction methods are generated by macros (`unary_op!`, `binary_op!`,
  `broadcast_binary_op!`). Each validates shapes and dtypes, calls the storage, and records an
  `Op` when `track_op()` is true (the tensor is a variable or has a tracked input).
- `tensor_cat.rs` implements `cat`: when every input is compatible with a 2D block copy it uses
  `copy2d`; otherwise it concatenates via strided copies.
- `indexer.rs` provides `.i(...)` indexing over ranges and integers.

### Shapes, layouts and strided iteration

- `shape.rs`: `Shape` (a `Vec<usize>`), `D` (`D::Minus1`, `D::Minus(n)`) and the `Dim`/`Dims`
  traits. Tuples of up to 6 dimensions and `Vec<usize>` convert into shapes.
- `layout.rs`: `Layout { shape, stride, start_offset }`, with helpers to transpose, narrow,
  broadcast (stride 0) and test contiguity.
- `strided_index.rs`:
  - `StridedIndex` iterates the storage offsets of a layout element by element.
  - `StridedBlocks` classifies a layout as a single contiguous block, uniform blocks or multiple
    blocks. This lets CPU kernels run tight loops over contiguous runs instead of per-element
    index arithmetic.

### DTypes

`dtype.rs`. `DType` has `U8, U32, I16, I32, I64, BF16, F16, F32, F64, F8E4M3` and the storage-only
`F6E2M3, F6E3M2, F4, F8E8M0` (`dummy_dtype.rs`, kept as raw bytes). The `WithDType` trait connects
Rust element types (from `half` and `float8`) to `DType` and to the CPU storage variants.

### Storage and backend dispatch

- `storage.rs`: `enum Storage { Cpu(CpuStorage), Cuda(CudaStorage), Metal(MetalStorage) }`. Each
  operation is a `match` over the operand variants. A `(Cpu, Cpu)` pair calls the CPU
  implementation, and so on; mixed pairs return `DeviceMismatchBinaryOp`. `same_device` and
  `same_dtype` are checked first. On Metal the device must be the same object, not just the same
  location, because the command queue is per device.
- `backend.rs`: the `BackendStorage` trait (~40 methods) and the `BackendDevice` trait:
  - **`BackendStorage`** covers `affine, powf, elu, reduce_op, cmp, to_dtype, unary_impl::<U>,
    binary_impl::<B>, where_cond, conv1d/2d`, their transposes, `avg/max_pool2d`, nearest and
    bilinear upsampling, `gather, scatter_set, scatter_add_set, index_select, index_add, matmul,
    copy_strided_src, copy2d` and `const_set`.
  - **`BackendDevice`** covers allocation (`zeros_impl`, `storage_from_slice`,
    `storage_from_cpu_storage`), random numbers (`rand_uniform`, `rand_normal`, `set_seed`) and
    `synchronize`.
- `op.rs`:
  - The autograd `Op` enum: `Binary`, `Unary`, `Cmp`, `Reduce`, `Matmul`, `Gather`,
    `IndexSelect`, `WhereCond`, `Conv1D/2D`, reshapes and the custom ops.
  - The `UnaryOpT` and `BinaryOpT` traits, which give each operation a name, a GPU kernel name and
    scalar plus vectorized implementations for every dtype. Backends are generic over these
    traits, so one `unary_impl::<Exp>` serves every unary operation.

### CPU backend

`src/cpu_backend/`, `src/cpu/`.

- **Storage:** `CpuStorage` is an enum of `Vec<T>`, one variant per dtype.
- **Element-wise operations:**
  - `cpu_backend/utils.rs` has `unary_map`, `unary_map_vec`, `binary_map` and `binary_map_vec`.
    They walk `StridedBlocks`, using vectorized slices for contiguous blocks and broadcasting
    fast paths for a contiguous operand against a stride-0 one.
  - The `Map1`/`Map2` traits dispatch a generic closure over the dtype variants.
- **SIMD:** `cpu/` holds the SIMD kernels used by reductions and some ops: `avx.rs`, `neon.rs` and
  `simd128.rs`, `features.rs` for runtime CPU feature detection, and `erf.rs`.
- **Matmul:** the `gemm` crate (`gemm::gemm` with `Parallelism::Rayon`), or MKL/Accelerate when
  those features are enabled (`mkl.rs`, `accelerate.rs`). Batched matmuls handle broadcast batch
  strides.
- **Convolutions:** im2col followed by a matmul (`Im2Col`, `Im2Col1D`; `USE_IM2COL_CONV1D`), with
  direct kernels parallelized over output channels via `rayon`. `cpu_backend/conv2d.rs` holds
  further 2D paths.
- **Copies:** `copy2d_` for 2D block copies, and `copy_strided_src_` for strided-to-contiguous
  copies.
- **Threading:** `rayon` inside operations. `utils.rs` provides `get_num_threads` and a
  spin-then-park `barrier_pool` used by the quantized matmul workers.

### CUDA backend

`src/cuda_backend/` (with `cudarc` 0.19).

- **Device and kernels:**
  - `device.rs`: `CudaDevice` wraps a cudarc context and stream. Each storage is a typed
    `CudaSlice`.
  - Kernels come from `candle-kernels` as PTX modules. `get_or_load_func(name, module)` loads a
    module once and caches its functions.
  - `get_or_load_custom_func` does the same for user PTX.
- **Element-wise, reductions, indexing, casts:** launches of templated kernels from
  `candle-kernels/src/*.cu` (`unary.cu`, `binary.cu`, `affine.cu`, `reduce.cu`, `indexing.cu`,
  `cast.cu`, `conv.cu`, `fill.cu`, `sort.cu`, `ternary.cu`). Layout metadata (dims and strides)
  is passed to the kernels, so non-contiguous inputs work without copies.
- **Matmul:** cuBLAS `gemm_strided_batched`, with the operands' transposition flags derived from
  their strides.
- **Optional:** `cudnn.rs` for cuDNN convolutions, and `cutile.rs`.
- **Build:** `candle-kernels/build.rs` uses `cudaforge::KernelBuilder` to compile `src/*.cu` to PTX
  (`-O3 -std=c++17 --expt-relaxed-constexpr`) and writes `ptx.rs`. The MoE and GGUF matmul
  kernels (`src/moe/*`, `mmvq_gguf.cu`, `mmq_gguf/`) are compiled statically and linked through
  `ffi.rs`.

### Metal backend

`src/metal_backend/`, `candle-metal-kernels/`.

- **Device:** `MetalDevice` (in `device.rs`) wraps an `objc2-metal` device and command queue.
  Storages are `MTLBuffer`s.
- **Shader compilation:**
  - `candle-metal-kernels/src/metal_src/*.metal` holds the shader sources: affine, binary, cast,
    conv, fill, gemv, indexing, MLX GEMM, MLX sort, quantized, random, reduce, scaled dot-product
    attention, sort, ternary and unary.
  - They are compiled at runtime with `new_library_with_source` (`kernel.rs::load_library`).
  - Compute pipelines are cached by name and function constants in a `RwLock<Pipelines>`.
- **Execution:**
  - `kernels/*.rs` set buffers and constants and dispatch each kernel.
  - Commands are batched into command buffers and flushed when full or when data is read back
    (`flush_and_wait_current`).
- **Matmul:** MLX's GEMM kernels (`mlx_gemm.rs`).

### Autograd

`src/backprop.rs`, `src/variable.rs`.

- **Variables:** `Var` wraps a `Tensor` created with `is_variable = true`. `Var::set` replaces its
  storage in place, which is how optimizers update parameters.
- **Graph walk:** `Tensor::backward` calls `sorted_nodes()`, a depth-first topological sort over
  the recorded `op`s that keeps only nodes leading to a variable. It then visits them in reverse,
  applying each `Op`'s derivative rule. Gradients accumulate in
  `GradStore(HashMap<TensorId, Tensor>)`.
- **Detaching:** intermediate gradients are detached unless the environment variable
  `CANDLE_GRAD_DO_NOT_DETACH` is set.

### Custom operations

`src/custom_op.rs`.

- **Traits:** `CustomOp1/2/3` provide `cpu_fwd`, optional `cuda_fwd` and `metal_fwd`, and optional
  `bwd`. `InplaceOp1/2/3` are the in-place variants.
- **Applying:** `Tensor::apply_op1/2/3` (and the `_no_bwd`/`_arc` forms) record the op for
  autograd, so custom ops participate in `backward`.

### Serialization

- **`safetensors.rs`:**
  - `load` and `save` for whole files.
  - `MmapedSafetensors` for memory-mapped, multi-file loading; tensors are read on `load(name)`.
  - `BufferedSafetensors` and `SliceSafetensors` for in-memory data.
  - `from_raw_buffer` builds tensors from raw bytes.
- **`npy.rs`, `pickle.rs`:** NumPy `.npy`/`.npz` and PyTorch `.pt`/`.pth` (an unpickler for the
  tensor subset).
- **`quantized/gguf_file.rs`:**
  - `Content::read` parses the header, metadata (`Value`) and tensor infos.
  - Tensors of the plain integer and f64 types are kept in `raw_tensor_infos`.
  - `tensor(reader, name, device)` reads one `QTensor`.
  - `write` writes a GGUF v2 file.
- **`quantized/ggml_file.rs`:** the older GGML format, and `qtensor_from_ggml`, which maps a GGML
  type id to a block type.

### Quantization

`src/quantized/`.

- **Block types:**
  - `k_quants.rs` defines the `GgmlType` trait (`BLCK_SIZE`, `VecDotType`, `to_float`,
    `from_float`, `vec_dot`, `vec_dot_2/4`). Its implementations are `BlockQ4_0, Q4_1, Q5_0,
    Q5_1, Q8_0, Q8_1, Q2K…Q8K` (`#[repr(C)]`, laid out byte-for-byte as in GGML), plus `f32`,
    `f16` and `bf16`.
  - `ternary.rs` adds `BlockQ2_0`, `BlockPQ2_0` and `BlockPTQ1_0`, with a `BlockQ8_0x<N>`
    activation block that matches their block size.
- **Matmul** (`k_quants::matmul`):
  - Activations are quantized to the weight type's `VecDotType` into a thread-local scratch
    buffer.
  - Output columns are computed in groups of four with `vec_dot_4`. For a single row (decode) the
    groups are split across `barrier_pool`; for several rows (prefill) work is tiled by rows and
    columns.
  - `repack.rs` and `repack_x86.rs` interleave weights for faster x86 dot products.
- **SIMD kernels:** `avx.rs`, `neon.rs` and `simd128.rs` hold the per-type dot products, selected
  at runtime (`has_avx2_fma`) or at compile time (`target_feature`).
- **Types and storage:**
  - `mod.rs`: `GgmlDType` (with its GGUF type ids) and the object-safe `QuantizedType` trait
    implemented for `Vec<T: GgmlType>`.
  - `QStorage { Cpu(Box<dyn QuantizedType>), Cuda, Metal }` and `QTensor`.
  - `QMatMul { QTensor, Tensor, TensorF16 }` dequantizes small or unsupported types to dense
    tensors.
- **GPU:**
  - `cuda.rs`: dequantize, matrix-vector (`dequantize_mul_mat_vec_*`, `mul_mat_vec_*_q8_1`), MMQ
    (`fast_mmq.rs`, `fast_mmvq.rs`) and indexed MoE kernels.
  - `metal.rs`: maps `GgmlDType` to the kernels in `quantized.metal`.
  - Both fall back to dequantizing on the CPU for types they lack.
- **Tokenizer:** `tokenizer.rs` builds a `tokenizers::Tokenizer` from GGUF metadata.

## candle-nn

- **Modules:**
  - `Module`/`ModuleT` are defined in candle-core (`lib.rs`) and re-exported. `Fn(&Tensor) ->
    Result<Tensor>` implements `Module`.
  - Layers are plain structs holding tensors: `Linear` (weight `(out, in)`, matmul with the
    transposed weight), `Embedding` (`index_select`), `Conv1d/2d`, `LayerNorm`, `RmsNorm`,
    `GroupNorm`, `BatchNorm`, `LSTM`/`GRU`, `Sequential`.
- **Fused ops** (`ops.rs`): `CustomOp`s with CPU, CUDA and Metal kernels for `Sigmoid`,
  `SoftmaxLastDim`, `RmsNorm`, `LayerNorm` and `Sdpa` (Metal scaled dot-product attention).
  `rotary_emb.rs` has `rope`, `rope_i` and `rope_thd`.
- **Attention:** `cpu_flash_attention.rs` and `attention/cpu_flash/` implement a CPU flash
  attention, and `attention/varlen.rs` variable-length attention.
- **MoE:** `moe/` and `moe.rs` hold mixture-of-experts helpers.
- **KV caches** (`kv_cache.rs`): `Cache`/`KvCache` (preallocated, written with `slice_set`),
  `RotatingCache`/`RotatingKvCache` (sliding window), `ScatteredKvCache` (paged), `ConcatKvCache`,
  `InterleavedKvCache` and `RawInterleavedKvCache`.
- **VarBuilder** (`var_builder.rs`):
  - `VarBuilderArgs<B: Backend>` holds a path prefix, a dtype and a device; `pp(name)` pushes a
    segment.
  - `VarBuilder<'a>` is `VarBuilderArgs<Box<dyn SimpleBackend>>`. `SimpleBackend` is implemented
    for `MmapedSafetensors`, `BufferedSafetensors`, `SliceSafetensors`, `HashMap<String, Tensor>`,
    `VarMap` (creates variables with an `Init` on first request, for training), `Zeros`,
    `NpzTensors` and `PthTensors`.
  - `ShardedSafeTensors` implements `Backend` with per-tensor shard hints for tensor parallelism.
  - `get` checks the shape, then converts dtype and device.
- **Training:** `var_map.rs` is a thread-safe map of `Var`s with save and load. The `Optimizer`
  trait (`new(vars, config)`, `step(&GradStore)`) is implemented by `SGD` and `AdamW`.
  `loss.rs`, `init.rs` and `encoding.rs` (one-hot) complete it.
- **Sampling:** `sampling.rs` has sampling helpers used by generation.

## candle-transformers

- **Model files:**
  - Each `models/<name>.rs` (or directory) defines a `serde::Deserialize` `Config` matching the
    checkpoint's `config.json`, layer structs, and a `Model` with `new(&Config, VarBuilder)`,
    `forward(input_ids, offset)` and `clear_kv_cache()`.
  - Quantized variants (`quantized_<name>.rs`) build the same layers from a `gguf_file::Content`.
- **Shared code:**
  - `models/with_tracing.rs`: `Linear`, `Embedding`, `Conv2d`, `QMatMul`, `LayerNorm` and
    `RmsNorm` wrapped in `tracing` spans.
  - `quantized_nn.rs`: quantized layers.
  - `quantized_var_builder.rs`: a `VarBuilder` over GGUF files.
  - `utils.rs`: `repeat_kv`, causal-mask builders, the repeat penalty and hidden-state
    collection.
  - `fused_moe.rs`: MoE routing over fused expert weights.
- **Generation:** `generation/mod.rs` has `Sampling` (argmax, all, top-k, top-p, top-k-then-top-p,
  with temperature) and `LogitsProcessor`. `pipelines/text_generation.rs` holds the text pipeline,
  and `object_detection.rs` has non-maximum suppression.
- **Typical model internals:**
  - KV caches are kept as `Option<(Tensor, Tensor)>` per attention layer and extended with
    `Tensor::cat`.
  - Recurrent models keep state tensors.
  - Attention is computed explicitly (`matmul`, mask add, `softmax_last_dim`, `matmul`), or with
    flash attention on CUDA when the feature is enabled.
- **Tests:** `candle-transformers/tests/` compares models against golden fixtures produced by the
  reference implementations (`tests/fixtures/generate.py`), with helpers in `tests/common/`.

## Applications

- **`candle-examples`:**
  - `examples/<name>/main.rs` (~114 examples) parse arguments with `clap` and fetch files with
    `hf-hub` (`src/hub.rs`).
  - Each picks a device with `candle_examples::device(cpu)`, which prefers CUDA, then Metal, then
    the CPU.
  - Text output streams through `TokenOutputStream`.
  - The `buildtime-download` feature fetches example assets at build time.
- **`candle-wasm-examples`:** crates per model (bert, blip, llama2-c, moondream, phi, quant-qwen3,
  segment-anything, t5, whisper, yolo) built with `wasm-bindgen` and web workers.
- **`candle-pyo3`:** `pyo3` classes wrapping `Tensor` and `QTensor`, utility submodules
  (`candle_utils`, `candle_functional_m`, `candle_onnx_m`), packaged with maturin.
- **`candle-onnx`:** `onnx.proto3` compiled with `prost`. `eval.rs::simple_eval` interprets a
  graph node by node, mapping each ONNX operator to tensor operations.
- **`tensor-tools`:** `src/main.rs` lists, quantizes and converts safetensors, npz and GGUF files.

## Testing and benchmarks

- **Unit tests** sit next to the code (`#[cfg(test)]`).
- **Integration tests:**
  - `candle-core/tests/` covers tensors, layouts, indexing, conv, pooling, matmul, gradients,
    custom ops, serialization (with `.npy`/`.pt` fixtures), GGUF and quantization.
  - `candle-nn/tests/` covers ops, KV caches, normalization, losses, optimizers, RNNs, SDPA and
    flash attention.
  - `candle-transformers/tests/` holds the model fixture tests.
- **Multi-device tests:** the `test_device!` macro instantiates a test for the CPU, CUDA and Metal,
  each behind its feature.
- **Benchmarks:** `candle-core/benches/` uses `criterion` (affine, binary, broadcast, cat,
  contiguous, and others).
- **Formal checks:** `#[cfg(kani)] mod proofs` blocks in a few model files hold Kani bounded proofs
  of index arithmetic. The crate declares `check-cfg = ["cfg(kani)"]`.
